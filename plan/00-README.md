# Plan — the pre-product pipeline

Numbered docs run **in order**. Each one builds on the last. Don't skip — empty sections are fine, blank files are not.

| # | Doc | Question it answers |
|---|---|---|
| 01 | [IDEA](01-IDEA.md) | What's the raw thought? |
| 02 | [RESEARCH](02-RESEARCH.md) | Is it real — market, competitors, pain? |
| 03 | [MISSION](03-MISSION.md) | What are we actually trying to do? |
| 04 | [STAGES](04-STAGES.md) | What's the pipeline, and what are the exit criteria at each gate? |
| 05 | [ROLES](05-ROLES.md) | Who owns each stage, who signs off? |
| 06 | [OPTIONS](06-OPTIONS.md) | What paths could we take? |
| 07 | [DECISIONS](07-DECISIONS.md) | Which path did we pick, and why? |
| 08 | [BUSINESS_PLAN](08-BUSINESS_PLAN.md) | How does this make money / survive? |
| 09 | [RISKS](09-RISKS.md) | What could break, and what are we assuming? |
| 10 | [GLOSSARY](10-GLOSSARY.md) | Project-wide vocabulary (reference). |
| 11–12 | EXAMPLE-* | Small-scope reference specs (kept as examples) |

## Rule of thumb

Go one doc at a time. Don't open `08-BUSINESS_PLAN.md` until `07-DECISIONS.md` has real content. **04-STAGES** and **05-ROLES** are framework — read once, refer back often. **09-RISKS** and **10-GLOSSARY** are living registers — update as you go.

## Then what

When `plan/` is stable, move to [`../specs/`](../specs/) for the formal spec and the companion design doc (`05-DESIGN_v1.0.md`). UI prototypes and the project portal live in [`../dashboard/`](../dashboard/). See [04-STAGES.md](04-STAGES.md) for the full stage pipeline and exit criteria.
